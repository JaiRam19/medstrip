MedStrip

Photograph a medicine strip. A small team of agents reads the name and expiry date, looks up official warnings, checks the new medicine against your cabinet, and lets you ask questions about it in chat.

  • 4 agents in version 1
  • 3 more later
  • 2 apps
  • 6 failure drills
  • 2 to 3 days
Scope Flow Tech roles Agents Topics Messages Redis and S3 API Risk levels Failure drills Build order Done when

Scope

Version 1
  • Upload a strip photo and get a job id back right away.
  • Vision Reader, Drug Facts, Interaction Checker, Chat Concierge.
  • Cabinet of medicines per user, stored in Redis.
  • Retry, dead letter topic, and a "retake photo" outcome.
Later
  • Safety Reviewer (next, most interesting).
  • Schedule Planner and Expiry Watcher.
  • Login, real users, a front end beyond a simple page.
Safety rules. This is a learning project, not medical advice. Use your own photos or sample strips, never someone else's. No agent gives dosage advice or a diagnosis. Show "Not medical advice. Ask a pharmacist." in every chat answer and on every HIGH or UNKNOWN result.

Job status the user sees

UPLOADED→ READING→ LOOKING_UP→ CHECKING→ DONE or NEEDS_RETAKE FAILED

What each technology does

TechnologyJob in this project
S3 (LocalStack locally)Stores uploaded photos. Key is {userId}/{jobId}.jpg. Delete after 7 days.
KafkaMoves a job from one agent to the next. The upload returns at once and the agents work in the background.
RedisCabinet, job status, openFDA cache, duplicate-photo check, upload rate limit, chat memory.
Spring AIThe pipeline agents: vision reading, summarizing label text, risk rating. Structured output into Java records.
LangChain4jThe Chat Concierge: an AI service with tools and Redis-backed chat memory.
openFDAFree drug label API. Fields used: warnings, drug_interactions. Example: https://api.fda.gov/drug/label.json?search=openfda.brand_name:"ibuprofen"&limit=1

Two Spring Boot apps: medstrip-api (upload, status, cabinet, chat) and medstrip-agents (all Kafka consumers). Run Kafka, Kafka UI, Redis and LocalStack with Docker Compose. Use any vision-capable model, or a local one through Ollama.

Use 3 partitions on each main topic. The key is userId so one user's messages stay in order within each step.

Order is guaranteed per step, not across the whole pipeline. If one user uploads two photos within a few seconds, the second check can run before the first medicine reaches the cabinet. Accept this in version 1. It makes a good stretch drill later.

REST API (medstrip-api)

No login. Send a synthetic user in the X-User-Id header.

EndpointBehaviour
POST /photosMultipart image. Checks the rate limit (429), the duplicate hash (returns the existing jobId), then saves to S3, sets UPLOADED, publishes to Kafka, returns 202 with jobId.
GET /jobs/{jobId}Status, plus the result and reasons when finished.
GET /cabinetAll medicines for the user with expiry and last risk.
DELETE /cabinet/{medicineId}Remove a medicine.
POST /chatBody {"message": "..."}. Returns the Concierge answer.

Risk levels

LevelMeaningShown to the user as
LOWThe label text mentions no interaction with anything in the cabinet."No interaction found in the label. This is not a guarantee."
MEDIUMThe label advises caution, or two items share an ingredient class.The reason, plus "check with a pharmacist".
HIGHThe label warns against combining it with an item in the cabinet.The reason, plus "ask a pharmacist before taking both".
UNKNOWNNo label text was found, or the lookup failed."Could not check. Ask a pharmacist." Never shown as safe.

Failure drills

Build the success path first. For each drill, watch it break before you add the fix.

DrillWhat breaksRequired behaviourHow to trigger
1 Blurry photo Model returns a low confidence guess. Retrying will not help. Treat it as a result, not an error. Status NEEDS_RETAKE, nothing sent to the DLT. Upload a dark or blurred photo
2 Bad model output Model returns text that does not parse into the record. Retry twice, then DLT and status FAILED. Other jobs keep flowing. Make the prompt ask for free text, or mock the model
3 openFDA down Calls hang, the consumer falls behind, lag grows. 3 second timeout, backoff, serve from cache if present. If not, pass on unavailable and rate the result UNKNOWN. Block api.fda.gov or point the client at a dead port
4 Duplicate photo Same photo uploaded twice, or a message replayed, creates two cabinet entries. Hash check returns the first jobId. Cabinet write is idempotent on name, strength and expiry. Upload the same file twice, or replay the topic from the start
5 Worker crash Agent dies after doing its work but before the next step. Commit the offset only after the next event is sent. Each step checks job:{jobId} so a replay does nothing twice. Kill medstrip-agents mid-job, then restart
6 S3 object missing Event arrives but the image cannot be loaded. Retry with backoff in case of a short delay. Then DLT with the reason and status FAILED. Delete the object before the Vision Reader runs
